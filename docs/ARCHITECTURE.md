# 架构与关键不变量

## 1. 数据来源和持久化

本地嵌入式 PostgreSQL 由 PGlite 提供，`pgvector` 是实际加载的数据库扩展。所有资料、任务、知识清单、回答、SSE 事件、反馈和评测记录都存在数据库中。只有当前请求的 AbortController 与任务调度器运行状态存于内存。

| 数据 | 权威位置 | 边界 |
|---|---|---|
| 会话与身份 | sessions / users | Cookie 保存随机令牌，数据库只存 SHA-256 摘要 |
| 资料与修订 | documents | 原文与文件不可变，访问范围允许调整 |
| 任务尝试 | jobs | 阶段和 attempt 号控制重试结果提交 |
| 检索产物 | chunks | 来源坐标 + 索引配置 + pgvector 向量 |
| 知识发布 | releases / settings | 不可变清单与当前发布指针 |
| 问答运行 | runs / events | 正文、终态和递增事件在事务内更新 |
| 测试集 | datasets | 保存新版本，不覆盖旧测试题 |
| 评测 | eval_jobs | 每题每配置结果持久化，保留失败/取消 |

## 2. 入库与尝试隔离

`queued → parsing → chunking → indexing → ready`。

原始文件先保存，后台调度器从数据库读取任务。每阶段真实执行解析或索引工作，不用前端计时器伪造进度。阶段和文档状态在同一 SQL 事务更新。

处理结果先在内存准备，提交时锁定任务行，核对状态与尝试次数。取消后立即重试会增加 `attempts`，旧尝试迟到的成功/失败都不能改写新尝试。片段替换、文档就绪和任务就绪一次提交。

重启时，未完成入库阶段重排队。运行中的模型生成无法从原 token 恢复，因此保留已持久化正文、写入失败终态，并允许重新生成。评测恢复时保留已经记录的逐题结果。

## 3. 权限边界

API 不接受任意 `userId` 或 `role` 头作为授权。演示账号正常登录后获得有效期 24 小时的随机会话。所有可变接口校验来源和请求结构。

检索 SQL 先限定空间、可见范围、产品版本、发布清单和索引键。小库对完整授权集合计算向量与字面分数，不在向量 Top 30 截断后假装有独立关键词召回。

资料撤权会立即中止单空间内所有进行中的回答，包括尚未写入引用的检索阶段。这是首版保守策略，可能中止无关运行。模型调用前再次检查来源权限和 AbortSignal。

每次 SSE 回放、历史回答和引用读取重新授权。撤权不能抹去用户先前已收到的内容。管理诊断仅向知识运营者开放，创建、幂等回读、取消、列表、详情均使用同样的运行 DTO。

## 4. SSE：业务事件与传输错误

业务事件包含 `runId`、`sequence`、`type`、`payload`。事务先保存事件与正文/终态，再由 SSE 读取已提交事件发送。

客户端 TextDecoder 保留跨字节 UTF-8 状态，事件解析器保留半条事件。客户端以 runId 防止会话串流，以 sequence 去重；遇到间隙重连。当前回答每 50 ms 批量刷新，用户上滚时暂停自动跟随。

**连接错误不属于问答业务终态。** `/events` 的临时失败使用独立 `transport-error` 帧，不占业务序号，不写入 `events`。重连仍从上次实际处理的序号回放。只有持久化 `done` / `error` / `cancelled` 才结束业务运行。

取消先原子写入终态，再中止上游请求。已完成状态先提交时，取消返回已完成状态。所有后续增量在事务中检查终态，不能追加。

## 5. 检索与生成

本地演示向量是归一化的 48 维特征哈希，不能称为语义 Embedding。PostgreSQL 执行实际 `<=>` 余弦距离查询。A 使用向量排序 Top 1，B 使用字面命中、错误码精确命中和向量分数组合 Top 3。字面相关性门槛是演示规则，不是置信度。

生成适配器分为 `extractive-demo` 和 `openai-compatible`。前者只展示授权证据原文；后者将证据作为数据交给模型，并要求仅引用服务端来源 ID。系统不执行资料中的工具指令。

未知 `[S数字]` 引用会导致核验失败，不会生成可点击伪链接。引用 ID 合法只证明来源对应，内容支持度仍需复核。

模型 `stop` 或完整 `[DONE]` 协议标记才可完成；截断、过滤、工具调用结束和无终止的断流保留部分内容并失败。用量未返回则明确未知，不把字符数冒充计费 token。

## 6. 质量评测

每次评测绑定测试集、知识发布、provider。每题固定角色和产品版本，A/B 分别创建真实 AnswerRun，使用同一检索和生成链路。

规则检查“是否有证据/应否拒答”和明确关键词。界面称为规则命中，分母采用计划题数，完成、失败、取消、等待分别统计。人工复核单独保存，不被规则分数代替。

8 道默认题覆盖版本差异、错误码、缺资料、普通成员受限和运维授权。界面可编辑新版本，反馈可以转成带预期行为的回归题。

## 7. 尚未生产化的部分

数据、解析和调度器在单进程中运行；CPU 密集 PDF 处理未迁入独立 worker。没有多实例锁、分布式消息队列、实时成本预算或大规模召回压测。迁移路径见 SCOPE。
